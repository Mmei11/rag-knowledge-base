# 智能知识库 RAG 平台后续优化路线图

本文档用于记录当前 MVP 跑通之后的后续优化方向。项目当前已经完成基础链路：

```text
上传文档 -> 解析文本 -> 文本切块 -> Qwen Embedding -> pgvector 检索
-> Prompt 拼接 -> Qwen Plus 回答 -> 前端展示答案与引用
```

后续优化可以按“产品体验、RAG 效果、工程质量”三条线推进。

## 1. Prompt 模式配置化

### 目标

将当前写死在后端 `PromptBuilder.java` 里的回答规则，改成可配置、可切换的回答模式。

### 可支持模式

| 模式 | 说明 | 适合场景 |
| --- | --- | --- |
| 严格知识库模式 | 只能根据知识库资料回答，资料不足就拒答 | 企业知识库、制度问答 |
| 知识库优先模式 | 优先使用知识库，资料不足时允许使用通用知识补充 | 学习助手、个人知识库 |
| 通用问答模式 | 不强制依赖知识库，可作为普通 AI 助手使用 | 闲聊、通用问题 |
| 学习讲解模式 | 用通俗语言解释，再补充知识库依据 | 学习、复习、课程笔记 |

### 技术改造点

- 后端增加 `PromptMode` 枚举。
- 请求 DTO 增加 `promptMode` 字段。
- `PromptBuilder` 根据不同模式生成不同 Prompt。
- 前端聊天页增加模式选择控件。
- 测试覆盖不同 Prompt 模式。

### 当前状态

基础实现已完成：后端支持四种 Prompt 模式，前端聊天页支持发送问题时选择回答模式。

### 简历亮点

```text
支持多种 RAG Prompt 策略，可在严格知识库问答、知识库优先问答和学习讲解模式之间切换。
```

## 2. 引用体验优化

### 目标

让用户更清楚地知道答案来自哪些文档、哪些片段，提升可信度和可解释性。

### 可优化点

- 引用显示文件名，而不是只显示文档 ID。
- 引用显示页码。
- 引用显示相似度。
- 点击引用后，在右侧定位对应 chunk。
- 高亮引用原文中的关键句。
- 支持“展开/收起引用内容”。

### 技术改造点

- `document_chunks` 表增加 `page_number` 或 `metadata` 字段。
- PDF 解析时记录 chunk 所属页码。
- `RetrievedChunkResponse` 增加 `fileName`、`pageNumber` 等字段。
- 前端引用面板优化展示结构。

### 简历亮点

```text
实现答案引用溯源，支持文档片段预览、相似度展示和引用定位。
```

## 3. 检索质量优化

### 目标

提升 RAG 回答的准确性，让系统更容易找到真正相关的资料片段。

### 可优化点

- 增加相似度阈值，过滤明显无关的 chunk。
- 支持 TopK 参数调节。
- 增加关键词检索。
- 实现向量检索 + 关键词检索的混合检索。
- 增加 rerank 重排序。
- 支持按知识库、文档、时间范围过滤。

### 技术改造点

- `RagRetrievalRepository` 增加相似度阈值过滤。
- PostgreSQL 增加全文检索索引。
- 后端增加 Hybrid Search 服务。
- 可选接入 rerank 模型。

### 当前状态

基础实现已完成：支持按请求调节 TopK 和最低相关度；后端使用向量检索与关键词检索生成候选集，
再通过 RRF（倒数排名融合）合并排序。PostgreSQL 增加全文索引和 `pg_trgm` 子串索引，
其中子串索引用于弥补 PostgreSQL 原生全文检索对中文分词支持有限的问题。

当前版本支持按当前知识库内的文档多选，以及按文档上传日期范围筛选。尚未接入外部 rerank 模型。

### 简历亮点

```text
基于 pgvector 实现语义检索，并扩展相似度阈值、TopK 控制和混合检索策略。
```

## 4. 文档解析能力增强

### 目标

让知识库支持更多格式和更高质量的文档解析。

### 可优化点

- 支持 Word 文档：`.docx`
- 支持 Excel：`.xlsx`
- 支持网页 URL 导入。
- 支持 Markdown 标题结构识别。
- 支持 PDF 页码记录。
- 支持表格解析。
- 支持图片 OCR。

### 技术改造点

- 引入 Apache POI 解析 Word/Excel。
- 设计统一的 `DocumentParser` 接口扩展。
- 增加文档元数据字段。
- 对 Markdown 按标题层级切块。
- 对 PDF 按页提取文本。

### 简历亮点

```text
设计可扩展文档解析体系，支持 PDF、Markdown、纯文本等多格式文档接入。
```

## 5. 流式回答

### 目标

让 AI 回答像 ChatGPT 一样逐步输出，而不是等待完整答案生成后一次性返回。

### 可优化点

- 前端展示打字机式回答。
- 后端使用 SSE 推送模型输出。
- 支持回答中断。
- 支持加载状态和错误恢复。

### 技术改造点

- 后端新增 SSE 接口。
- Qwen 调用开启 stream 模式。
- 前端用 `EventSource` 或 Fetch Stream 接收输出。
- 聊天消息保存从“一次性保存”改为“生成完成后保存”。

### 简历亮点

```text
实现基于 SSE 的大模型流式问答，优化 RAG 系统交互体验。
```

## 6. 对话体验优化

### 目标

让智能问答从“单轮问答”升级为更完整的对话系统。

### 可优化点

- 删除会话。
- 重命名会话。
- 清空聊天记录。
- 追问时带历史上下文。
- 根据知识库自动生成推荐问题。
- 会话按更新时间排序。

### 技术改造点

- Chat Session 增加更新接口。
- Chat Session 增加删除接口。
- PromptBuilder 支持拼接历史消息。
- 前端增加会话管理按钮。

### 简历亮点

```text
实现多轮对话管理，支持历史上下文追问、会话持久化和会话管理。
```

## 7. 权限和用户体系增强

### 目标

让系统更接近真实企业级知识库产品。

### 可优化点

- 管理员角色。
- 知识库公开/私有。
- 知识库成员邀请。
- 知识库共享。
- 操作审计日志。
- 用户禁用与权限控制。

### 技术改造点

- 增加 `knowledge_base_members` 表。
- 增加权限校验服务。
- Controller 层增加权限控制。
- 增加操作日志表。

### 简历亮点

```text
实现基于用户和知识库维度的数据隔离，并扩展知识库共享与权限控制能力。
```

## 8. 工程化优化

### 目标

提升项目的可维护性、可部署性和专业度。

### 可优化点

- GitHub Actions 自动测试。
- Docker 镜像构建。
- Swagger/OpenAPI 接口文档。
- 统一日志 traceId。
- 统一错误码文档。
- 生产环境配置说明。
- 前端构建检查和代码规范。

### 技术改造点

- 增加 `.github/workflows/backend-test.yml`。
- 接入 Springdoc OpenAPI。
- 增加请求日志拦截器。
- 增加生产部署文档。

### 简历亮点

```text
完善工程化体系，支持 Docker Compose 一键部署、自动化测试和接口文档生成。
```

## 推荐推进顺序

建议后续按以下顺序推进：

1. Prompt 模式配置化
2. 引用体验优化
3. 检索质量优化
4. 对话体验优化
5. 流式回答
6. 文档解析能力增强
7. 权限和用户体系增强
8. 工程化优化

其中前 4 项最适合近期继续做，因为它们和当前 MVP 关联最紧密，改完后能明显提升产品完成度。

## 下一步建议

优先进入“Prompt 模式配置化”。这一项基于当前已经完成的宽松 Prompt 改造，改动范围适中，学习价值也高。
